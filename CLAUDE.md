# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Website for **Mechbridge International MEP Consultants** (logo and title: Mechbridge International, domain mechbridgegroup.com). It's consultancy first: HVAC, firefighting and plumbing engineering, MEP design, and estimation/project management. Training (one course), the GCC-ready internship package, careers and certificate verification sit alongside, and there's a staff portal. Product truth and brand constraints live in `PRODUCT.md`. Read it before changing copy.

## Commands

```bash
npm run dev           # Astro dev server :4321 (pages + /api, uses ./data)
npm run build         # VPS production build: dist/client (static) + dist/server/entry.mjs (Node)
npm start             # run the production server (HOST, PORT, DATA_DIR from env)
npm run build:demo    # static demo build (DEMO=1): no server, data in localStorage
npm run deploy:pages  # demo build with base /website, force-push dist/ to gh-pages → https://mechbridge.github.io/website/
npm run admin:create -- --email a@b.com --name "Name" --role superadmin   # create/reset a staff account (prompts for password)
node scripts/serve-local.mjs   # local prod server on :4322 (.claude/launch.json "mechbridge-prod")
```

Going live (DNS, VPS, website, mail server, Roundcube) is in `GO-LIVE.md`; `deploy/` holds the nginx, systemd, backup and mailbox scripts. Share cards in `public/og/` are generated by `node scripts/make-og.mjs` (re-run after changing a page title or photo). SEO: per-page `og`, `breadcrumbs` and `jsonLd` props on `Base.astro`, `robots.txt` and `sitemap-images.xml` endpoints in `src/pages/`, and noindex on the GitHub demo.

There are no tests or linters. Both `npm run build` and `npm run build:demo` must pass. VPS setup is in `DEPLOY-VPS.md`. `brand-theme/` is a git submodule (Mechbridge/colorscheme), so clone with `--recurse-submodules`.

## Architecture: one codebase, two builds

- **`astro.config.mjs`**: when `DEMO` is unset, it uses `@astrojs/node` standalone, and a tiny integration `injectRoute`s `/api/[...path]` → `src/server/api.ts` (`prerender: false`). With `DEMO=1` there's no adapter and no API, so the output is pure static. `PUBLIC_DEMO` is defined at build time. `SITE_URL` and `BASE_PATH` are only for the Pages preview. Every root-relative link goes through `u()` from `src/lib/url.ts`, and comparisons use `stripBase()`. In Git Bash, set `MSYS_NO_PATHCONV=1` when passing `BASE_PATH`.
- **Client API** (`src/lib/api/`): `client.ts` exports `api` = `httpApi` (fetches `/api`) or `demoApi` (localStorage, seeded sample data, demo logins `*@demo.mechbridge` / `demo1234`). Public pages and the admin portal only ever use `api`, so any new data feature needs both implementations plus the server route. Shared shapes are in `types.ts`. The role matrix (`leadTypesFor`, `postingKindsFor`, `canManageCertificates`…) and the certificate code format (`MBI-YYYY-XXXXXX`) are in `src/lib/roles.ts`, and both server and UI use them. Roles: superadmin, hr (jobs, internships and their leads), training (training batches), sales (proposal, training, contact and support leads), documentation (certificates). On top of the role, `users.perms` holds extra per-person access (`PERMS`, `hasPerm`; today only `drafter`), toggled in Staff accounts.
- **Server** (`src/server/`): `core.mjs` (plain JS so `scripts/admin-create.mjs` can share it) holds the SQLite schema through Node's built-in `node:sqlite` (Node ≥ 22.13; externalised in Vite) and scrypt hashing. `db.ts` holds the queries. `api.ts` is one router with role checks, an Origin-vs-Host check on writes, in-memory rate limits, and CV uploads to `DATA_DIR/uploads`. `notify.ts` sends optional SMTP lead alerts. Astro's own `checkOrigin` is off on purpose (it misfires behind proxies).
- **Postings** (jobs, internship intakes, training batches) share one `postings` table with a `kind` column. Statuses: `draft` (hidden), `open`, `closed` (still listed publicly with a Closed pill, "no longer available" text and a disabled button; the 6 most recent per kind) and `archived` (hidden). Public pages render them client-side with `src/scripts/postings.ts`, which uses `textContent` only because posting text is staff-entered. Never put DB text into `innerHTML`.
- **Admin** (`/admin`, `src/scripts/admin/app.ts`) is a hash-routed vanilla TS app inside `layouts/Admin.astro` (noindex, `styles/admin.css`). `/admin/certificate?id=` is the A4 print view, with its QR code from the `qrcode` package.
- **Admin lists are paged on the server** (`Paged<T>` in `types.ts`, max 100 per page). Leads, postings and certificates return one page plus per-status `counts` for the tabs. Filters (status, type, country, date range, CV, posting, assignee, search, sort) live in the hash query (`#/leads?status=new&range=30&page=2`). Shared UI blocks in `app.ts`: `tabs`, `dateRange` (presets plus custom), `pager`, `Selection` (shift-click ranges, kept across pages) and `bulkBar`.
- **Lead pipeline**: `new → contacted → qualified → distributed → converted`, or `closed`. "Distributed" records who the lead was handed to (`distributed_to`, `distributed_at`). Leads can be assigned to staff (`assigned_to`). Every change is written to `lead_events` and shown as the lead history. Bulk endpoints: `/api/admin/{leads,postings,certificates}/bulk`.
- **Lead alert email** (`notify.ts`): `leadEmailHtml` is a table-and-inline-style brand email (navy header with `public/logo/mechbridge-email.png`, cream body, "Open in staff portal" button to `#/leads?open=<id>`), sent with a text part. All lead text goes through `esc()`.
- **Mailboxes** (`#/mailboxes`, superadmin): `src/server/mail.ts` runs the root helper `deploy/mb-mailbox` (installed at `/usr/local/sbin/mb-mailbox`) via `sudo -n` and the single rule in `deploy/sudoers-mechbridge`; passwords go over stdin, never argv. Mailbox data lives in `/var/lib/mailboxes` (Dovecot passwd-file `users`, Postfix `vmailbox`) because the service's `ProtectSystem=full` makes `/etc` read-only, and `NoNewPrivileges` is off for sudo. Without the helper, dev uses a mock file in `DATA_DIR`; the demo uses localStorage. Address and password rules are shared in `roles.ts` (`mailAddressError`, `mailPasswordError`) and repeated in the bash helper, so change both together.
- **Mail drafter** (`#/drafter`, superadmin or the `drafter` perm): client-only; `src/lib/mail-html.ts` turns plain text (blank-line paragraphs, `- ` bullets, `1. ` steps, CAPS or `# ` headings, `> ` notes, `**bold**`) into inline-styled email HTML, copied to the clipboard as rich text. The same file builds the signature preview; `deploy/roundcube/mechbridge/mechbridge.php` builds the real webmail signature with the same design, so change both together.
- **Webmail** (Roundcube): the `mechbridge` plugin in `deploy/roundcube/mechbridge` brands the sign-in page (`login.css`, `logo.svg`) and reads `/var/lib/mailboxes/webmail.json` (settings for everyone, `cleanWebmailSettings` in roles.ts) and `/var/lib/mailboxes/names` (sender names), both written by `mb-mailbox settings` / `mb-mailbox name` from the portal. Install steps: GO-LIVE.md 8.1.
- **Dropdowns**: `src/scripts/select.ts` (loaded by Base and Admin layouts) wraps every `<select>` in `.msel` and replaces only the native popup with a rounded list that takes its colours from the field. The real select keeps value, labels and change events; opt out with `data-native`. Style hooks: `.msel`, `.msel-pop`, `.msel-opt` in global.css.
- **Portal on phones** (below 700px): tables become cards using the `data-label` that `tableEl` sets on every cell; mark the main cell `adm-primary` (or include an `.adm-row-link`) so it leads the card. Filters other than search fold behind a toggle (`foldFilters`). Below 900px a sticky top bar opens the sidebar.
- **Schema migrations**: versioned in `MIGRATIONS` in `core.mjs` and tracked by `PRAGMA user_version`. Add new ones at the end and never edit old ones.
- **Content data**: the five services with full scope lists, plus `projectProcess` and `codesWeUse`, are in `src/data/services.ts`. That feeds `/services`, `/services/[slug]`, the nav dropdown, the footer and the home sections. The single training course and the internship package are in `src/data/course.ts`. Names, emails, offices and nav are in `src/data/site.ts`.
- **Forms**: one `EnquiryForm.astro` handles every lead type (`types` prop limits the topic select; `cv` adds the upload; `[data-ref]` holds the posting id set by `pickInForm`). `/contact?topic=training` preselects a topic.
- **Layout/motion**: `Base.astro` loads the fonts and `global.css` (which imports `brand-theme/tokens.css`), the `Nav` (with the Services dropdown panel), and the `#smooth-wrapper` for GSAP ScrollSmoother. `motion.ts` hooks are `[data-enter]`, `[data-split]`, `[data-reveal-img]`, `[data-count]`. `ImageSlot` swaps in `public/images/<id>.webp` when the file exists, otherwise it shows a blueprint placeholder. `IMAGES.md` lists every slot.

### Home page clay background

`index.astro` has the hero, then `#clay` with exactly **10** `.cs` sections over the three.js clay scene (`public/bg/mb-clay-background.js`, a modified copy of `background-design/`, so edit the public copy). Grounds per section: navy, navy, cream, deep navy, navy-900, light cream, near-black, navy, cream, navy (cream sections use `theme-cream`). `src/scripts/home-bg.ts` passes the real section boundaries as `bands`. The canvas and ground colour layer are `position: fixed` in Base's `outside` slot because ScrollSmoother breaks sticky positioning. Piece positions are in `clayDesktop`/`clayMobile`. Content sits on the side away from the piece (`cs--L`/`cs--R`). Below 1100px (phones and tablets, `data-band`), pieces sit in a top band capped at 168px above a frosted card, and the cord runs down the side gutter instead of crossing text.

## Brand and content rules

- Colours: Midnight Navy `#1A2841`, Old Cream `#F0E1CE`, Vintage Red `#B11722`. Never red text on navy (use `red-300`). Glass and `FlutedGlass` appear only over photos or the clay scene.
- Logo: `src/data/logo-inner.svg` (skyscraper "M" monogram + MECHBRIDGE wordmark, `currentColor`), rendered by `Logo.astro` (`variant="mark"` crops to the monogram). Static colour versions are in `public/logo/`.
- **No team names, portraits or team photos anywhere.** Alt text must not claim a photo shows Mechbridge staff.
- Don't invent figures, clients, fees, durations or credentials. Confirmed: 15+ years in the industry, 7,000+ projects completed, projects in 10+ countries (`site.years`, `track` in `src/data/site.ts`). Open items are tracked in `CONTENT-TODO.md`.
- Clients named on the site are only the "Recent highlights" in `src/data/projects.ts` (Jasleena’s Residence, Mohammed’s Residence, Zangos), shown by `Highlights.astro` after the home page clay zone. Present them as a few recent projects, never as the client list, and don't claim a scope for them that the client hasn't confirmed.
- Training: one course with three modules (HVAC, firefighting, plumbing). Don't list AutoCAD, Revit MEP or BIM as course content (they stay in the MEP design service). Don't mention electrical or civil engineering streams anywhere. Instalments with Tabby and Tamara are offered for the course (`PayPartners.astro`; official logo files go in `public/brand/tabby.*` and `tamara.*`).
- No designer or developer credit in the footer.
- No eyebrow/kicker labels above headings. Write copy in plain, specific sentences with no em dashes.
- Locations: headquartered in Dubai (Unbox, World Trade Center), operating from Dubai and Kozhikode, India (`offices` in `src/data/site.ts` holds the full addresses). Market globally with the GCC first but unstated: lists read GCC states, India, then "Worldwide" (`servesWorld`); hiring stays the GCC states and India (`servesShort`). Say "GCC", never "Gulf".
- Training is online-only in practice, but never advertise that or any classroom/office training. Use "live, instructor-led sessions".
- Emails: connect@ (proposals, training), support@, careers@ (job leads), intern@ (internship leads). `EnquiryForm` takes a `mail` prop, and `notify.ts` routes alerts by lead type.
